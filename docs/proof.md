# Proof: how Docket is measured

This file was written on 4 Nov 2026 at 13:05 IST and amended at 13:11 IST to match core's reader input, still before any agreement run. The lead commits it before `eval/run_agreement.py` makes its first model call, so the git history shows the bar came first. ## Dataset

CHECK-MAT: scanned handwritten solutions to the Russian Unified State Exam profile maths tasks 13 to 19, each with the official expert grade ([repo](https://github.com/Karifannaa/Auto-check-EGE-math), [paper](https://arxiv.org/abs/2507.22958)). The repo README states the MIT licence for code and data. Russian maths scripts stand in for any scheme-marked handwritten exam.

- Scripts are enumerated in code by `eval/slice.py` from `dataset_benchmark/<task>/<example>/<solution>/without_answer/*.png`, the same folders core's loader (`docket.checkmat.all_scripts`) reads. The official grade is the `estimate_<n>` in the file name. Multi-page scripts are sent as all their pages, in page order.
- What each reader sees: the student's pages, then the example's official statement, solution and criteria image (`<example>_solve_true.png`), labelled as the reference. This is CHECK-MAT's own "with true solution" mode. A real marker holds the official solution, so this is the realistic setting.
- The official grade is a total per script. CHECK-MAT holds no per-criterion expert marks, so every agreement metric is on the script total.

## Held-out slice

- **Primary: all 122 scripts.** Nothing in Docket was tuned on CHECK-MAT grades; the readers see only the scheme and the scans.
- **Fallback, fixed now:** if the measured pace after the first 10 scripts of run 1 shows the three runs cannot finish by 5 Nov 05:00 IST inside the free-tier limits, every setup and every run uses the seeded subset in `eval/slice_seeded61.json` (61 scripts, stratified by task, seed 20261104), and the results files say so. The subset was written before any run and is committed with this file.
- **If a provider's daily quota stops the runs:** Gemini's free-tier day resets at midnight Pacific time, after the deadline, so a daily cap cannot be waited out. If a daily cap stops run 2 or 3, those runs use the seeded 61-script subset, run 1 is also scored on its rows for those 61 scripts, and the three-run spread and the bar are reported on the seeded subset. Run 1's full-slice numbers are then reported beside them as a single run, labelled as one run.
- A script whose reader call still fails after the backoff budget is an error, not a wrong answer. It is dropped from **all three setups** for that run, and the count of dropped scripts is reported per run.

## The three setups

All three use the same readings, so the comparison isolates the decision rule and not luck in the calls.

1. **Docket**: reader A and reader B (two model families, ids in each results file) read every criterion; plain code applies the scheme; the comparator signs a script when the readers agree on every criterion within core's thresholds (`DOCKET_MARGIN_THRESHOLD`, `DOCKET_MIN_CONFIDENCE`, recorded in each results file), and routes each other criterion to the teacher interrupt.
2. **Reader A alone**: reader A's per-criterion readings, summed by the same scheme code, no comparator, no teacher.
3. **Reader B alone**: the same for reader B.

**Teacher in the eval.** No live teacher answers the interrupt during the measurement. The official expert grade stands in for the teacher: when a script has any criterion routed to the teacher, Docket's total for that script is the official total. This makes setup 1's whole-slice number partly true by construction, so it is never the headline. It measures teacher load, and the headline is what Docket does without a teacher.

## Metrics

Per run, per setup:

- **Exact**: share of scripts whose total equals the official grade.
- **Within one**: share whose total is within one point of the official grade.

Docket only:

- **Commits**: share of scripts signed with no teacher (every criterion agreed).
- **Exact when it commits**: exact agreement on those scripts only. On these scripts both readers gave the same reading of every criterion, so a single reader's agreement on the same subset is the same number by construction; the comparison that matters is against a single reader's whole-slice agreement, which is what one model marking alone would deliver. This is the headline, in the form "matches the official grade on X% of scripts; Y in 10 when it signs without a teacher".
- **Teacher-free floor**: Docket's total with every routed criterion given the lower of the two readings (a criterion either reader marks not met counts as not met), on the whole slice, no teacher. This is the full-slice comparison with no human against a single reader.
- **With teacher stand-in**: whole-slice exact where routed scripts take the official grade (see above). Reported, labelled, never headlined.
- **Teacher load**: share of criteria routed to the teacher, and share of scripts with at least one routed criterion.
- **Does the interrupt catch real errors**: on scripts routed to the teacher, the share where the official total differs from reader A's total, from reader B's total, from at least one, and from both.

Speed and cost: seconds per script (wall time of both readers plus code, from the run log), tokens per script per reader. Groq's free tier costs $0; the price-sheet estimate at each model's public per-token price is reported beside it, labelled as an estimate with the price page's URL.

## Runs and spread

Each setup is run **three times** on the same slice with fresh model calls: the run id is part of the response-cache key, so run 2 and run 3 never reuse run 1's answers. Reader settings (temperature, prompt) are core's defaults, recorded in each results file. Reported per metric: the mean, min and max of the three runs. **Spread** = max minus min.

If the spread of either side is larger than the gap between Docket and a baseline, the gap is reported as within noise, whatever its sign.

## The bar, fixed before running

Let `best` be the higher of reader A alone and reader B alone on mean exact agreement.

| Claim | Counts as a win | Reported as a loss |
|---|---|---|
| Exact when it commits beats a single reader | Docket's mean exact-when-commits is at least 10 points above that reader's mean whole-slice exact, and the gap exceeds both spreads | Docket's mean exact-when-commits is at or below that reader's mean whole-slice exact |
| Teacher-free floor beats a single reader | the floor's mean exact is at least 5 points above `best`, and the gap exceeds both spreads | the floor's mean exact is below `best`'s mean |
| Docket commits often enough to matter | commits on at least 40% of scripts (mean of runs) | commits on fewer than 25%: the headline is then printed with "signs without a teacher on fewer than one in four scripts" |
| The interrupt catches real errors | on routed scripts, the official total differs from at least one reader on at least 80% | below 50% |

Anything between the win and loss columns is reported as "no clear result" with the numbers. A loss is printed in the README and the post exactly as measured.

For reference only, the table also shows the best published single-model result on this dataset in the same "with true solution" mode, read from the CHECK-MAT repo's own `model_results` files (`eval/published_baselines.py`). Docket did not run those models, and they are not part of the bar.

## Robustness checks (each N of N)

- **Tamper** (`eval/tamper_test.py`): for N signed credentials and the signed revocation list, flip one byte in each byte class (a digit of a mark, a letter of an id, a hex digit of the image hash, a JSON punctuation byte, a byte of the signature) and verify with the published public key. Win: N of N fail. Any tampered copy that verifies is a loss and is printed.
- **Blind check** (`eval/blind_check.py`): each reader gets the grading request for every script in the slice with the scan removed. Win: the reader declines on every one. Each grade it gives anyway is counted and printed.
- **Signing guard** (`eval/guard_test.py`): inject a credential with a missing reading and one with a stale scheme version into the signing path. Win: the guard blocks N of N before KMS is called.
- **Re-mark** (`eval/remark_test.py`): bump the scheme from v1 to v2; count scripts re-marked, credentials revoked and re-issued, and the seconds it took. Win: every script whose total changes gets a new credential and its old one is on the signed revocation list; scripts whose total does not change keep theirs (if core re-issues every credential under the new version instead, the count says so).
